第 0 部分 · 设计理由与取舍

这份 IA 做了什么判断

对应 content-spec 的 data-screen-ref="S00"「设计理由与取舍」卡。

一句话定位

四个一级页面承载全部业务：课程助手（对话式入口）、我的课表（只读事实）、学习计划（显式授权后落库）、管理中心（管理员专用，与助手完全分离的第二条权限路径）。

适用场景

封闭试点的桌面浏览器（≥1366×768）与 390×844 窄屏学生主流程；单一学校时区 Asia/Shanghai。

不适用场景

需要跨设备历史、会话分享链接、周课表、提醒推送、OCR、教务同步的场景——本期均未承诺，IA 不为其预留入口。

优点

  • 路由只有 11 个，学生侧 4 个，可逐条写出守卫规则与越权行为。
  • 助手与管理中心在权限路径上物理分离：管理员向助手提问也只拿到本人的课表（PRD §3），不存在"管理数据从对话泄漏"的路径。
  • 课表、计划、后台全部可深链可分享可回退；只有助手对话刻意不深链，取舍理由单列（见第 2 部分）。
  • "空结果"与"读取失败"在 IA 层就是两条不同分支（S08 ①②），不会在实现时被合并成一个"暂无数据"。

代价

  • 刷新助手页会丢失本轮对话（DEC-01 / HLD-D03 / CHAT-03），用户感知是"退步"；必须用显式提示兑现诚实，而不是伪装恢复。
  • 管理中心在窄屏只能横向滚动表格（NFR-COMP-001 允许），不额外做移动端管理 IA。
  • 对话过程只能展示可核实动作，不能展示模型推理，过程区的信息量天然比"AI 思考流"少。

  • 管理中心不是"助手的第五个标签"：它是独立权限路径，入口由 GET /me 返回的能力集合决定是否渲染；隐藏菜单只承担界面引导，真正的拒绝发生在服务端（403 FORBIDDEN）。

2.1 通用准则与本项目约束的冲突：深链 vs 临时会话

通用 UI/UX 准则（我们遵守的那一半）

Deep Linking：URL 应反映当前状态，便于分享与浏览器前进/后退。

本项目在持久状态页面上完全遵守它：

  • 课表 /schedule?date=2026-10-22 —— 日期进 URL，可分享"周四的课表"，后退回到上一个日期。
  • 计划 /plans/:id、/plans/new —— 计划是持久资源，URL 指向的必须是刷新后仍存在的实体。
  • 管理中心各页 /admin/courses、/admin/schedules、/admin/documents、/admin/document-batches/{id}、/admin/students —— 可深链、可收藏、可回退；批次详情尤其需要可分享，便于管理员互相核对。

判据：URL 里出现的东西，刷新后必须仍然成立。课表日期、计划 id、批次 id 都满足这一条。

刻意不遵守的那一半（含理由）

助手对话不进入 URL。以下临时标识一律不进地址栏：conversation_id、草稿 draft_id / draft_version、本轮 request_id / operation_id、以及对话正文与引用列表。

理由：会话只存在于当前浏览器标签页的内存里，刷新、关闭、退出后不保证恢复（DEC-01 临时上下文；HLD-D03 浏览器仅内存保存不透明 Bearer 会话、刷新需重新登录、不自动续期；PRD CHAT-03 临时会话边界；HLD-D11 对话正文只驻留浏览器与运行内存）。把 conversation_id 写进 URL，等于向用户承诺一个不存在的恢复能力：刷新之后 URL 还在，看起来"这段对话还在那儿"，但内容已经不可恢复。用户会把它当 bug，也会把它当"服务端应该存着"的证据。

这比"URL 不反映状态"更糟：前者是诚实的能力缺口，后者是虚假的能力承诺。所以这里宁可违反通用准则。

替代方案：把"可回退 / 可分享"的诉求在助手页部分兑现（不尝试恢复对话）

  1. URL 保持 /assistant，不带任何会话参数。刷新后落到助手空闲态（S02），而不是"加载中"或空白页。
  2. 空闲态顶部给一句明确提示（对应 content-spec S02 边界提示条的语义）："对话只保存在当前浏览器标签页，刷新或关闭后不会恢复；已保存的计划不受影响。" 刷新后额外给一次性提示："上次对话未保存，刷新后无法恢复。" —— 说明发生了什么，而不是暗示可以恢复。
  3. 把"想留住"的内容路由到持久资源：对话里产出的计划，唯一可靠的留存路径是显式保存为计划（S06 → POST /me/drafts/{draft_id}/save），保存成功后给 plan_id 与「打开计划」按钮，跳转到可深链的 /plans/:id。这样"可分享"的诉求被转移到计划页，而不是留在对话页。
  4. 浏览器后退不等于退出助手：在助手页内不产生历史条目（不使用 hash/query 记录轮次），后退离开助手页时按常规导航处理；不做"返回上一轮对话"的伪历史。
  5. 断线/刷新时的核实入口：若刷新发生在执行中，UI 不假设结果，提示"本轮结果尚未确认"，并提供「查询写入状态」（GET /me/write-operations/{operation_id}）；operation_id 留在内存，不进 URL。

评审结论：这是一处有意识的取舍，不是遗漏。判据是"URL 里出现的东西刷新后必须仍然成立"，助手对话不满足该判据，因此不进入 URL；同时用"明确提示 + 把留存诉求转移到计划页"补偿可用性。

2.2 未登录与越权的统一处理

守卫行为与后端错误码的对应；前端不自行编造错误码，全部按 SRS §8 语义呈现。
情形客户端守卫动作服务端对应界面呈现
未登录访问受保护路由跳 /login，把原目标（含查询串）存入内存中的 redirect；登录成功后原样返回401 AUTH_REQUIRED整页登录页 + 顶部一句"请先登录后继续"
会话过期（2 小时到点）或令牌被撤销立即停止后续请求，清空内存中的身份、对话与草稿引用，跳 /login401 SESSION_EXPIRED整页登录页 + "登录会话已到期，请重新登录"
学生访问 /admin/*渲染通用拒绝页：不回显目标 path 的语义、不提示"该页面存在但无权限"、不提供"申请权限"入口403 FORBIDDEN整页拒绝页（中性色，非错误红）："你没有访问该页面的权限。"
访问不属于本人的 /plans/:id，或不存在 id不区分两种情况，同一页面同一文案404 RESOURCE_NOT_FOUND整页未找到："没有找到这个页面或内容。"
流式对话中身份失效（过期/撤销/禁用）终止连接，不展示任何私有内容；不再发送后续请求SSE error 只返回通用认证错误（AUTH_REQUIRED / SESSION_EXPIRED）对话区替换为整块认证失效提示 + 「重新登录」

为什么越权用通用拒绝页而不是"权限不足，请联系管理员"的详情页：404 与 403 的区别本身就会泄漏资源是否存在（SRS §8：404「不显示目标是否真实存在」）。统一拒绝页把"不存在"和"无权"合并成同一个对外观感，避免通过路由探测后台结构。

窄屏 390×844（S13）

  • 导航形态差异：顶部粘性主导航 → 底部 tab 栏（助手 / 课表 / 计划 / 更多），触控目标 ≥44×44。
  • 管理中心不在 tab 栏占位，收进「更多」抽屉：学生看不到该入口，管理员看到四项二级菜单。
  • 助手：单列；过程区折叠为一行摘要（"正在检索课程资料 · 进行中"），可展开；输入区吸底；三个示例入口换行或横滑（点击只填入输入框，不自动提交）。
  • 我的课表：卡片式单列，无横向滚动。
  • 管理中心：允许表格横向滚动（NFR-COMP-001 明确允许），但保留表头 sticky 与首列（课程代码 / 文件名）固定，避免滚动后失去参照。

4.3 生成并保存计划

对应 S06 / S09；/me/drafts/{draft_id}、/me/drafts/{draft_id}/save、/me/write-operations/{operation_id}；PRD §5.3、PLAN；SRS §7.3
① 草稿「未保存」助手生成草稿卡，同时有文字与视觉两重"未保存"标记；依据类型显式标注（本人课表 / 课程资料〔资料 1〕）。status 事件返回 draft_id + draft_version ▸ ② 保存许可只有当前用户可确定的直接指令才授予许可（DEC-06）："保存为我的计划"按钮或明确的"保存刚才这份"。歧义、否定、引用内容不授权。改草稿正文会生成新版本，旧许可失效。 ▸ ③ 幂等写入同一用户同一创建操作最多一份计划（INV-02）；无有效许可的助手请求产生零份持久计划（INV-03）。POST /me/drafts/{draft_id}/save（draft_version + Idempotency-Key）
成功 ▸ S06 保存成功「已保存 · 计划编号 plan_7Q2F9K」+ 主按钮「打开计划」→ 跳 /plans/:id（可深链的持久资源）。对勾图标 + 文字，不能只靠绿色。status = created
幂等命中 ▸ 同一份计划，不新建重复提交同一操作只得到同一份计划；提示小字"重复提交同一操作只会得到同一份计划"。同轮第二次创建 → 409 SAVE_LIMIT_REACHED。status = existing（plan_id 与首次一致）

为什么"待确认"必须是一个独立分支而不是失败分支：SRS §7.3 规定提交异常导致结果未知时对外显示 pending 或 recovering，并通过持久数据库状态核实；后端详细设计 §12.2 补充"数据库不可用且不能核实时返回 503，客户端仍显示待确认，不将其转换为 failed"。IA 上把它画成独立节点，是为了让"重试"永远不会被实现成一个新的幂等键。

5.1 每个状态 UI 显示什么

事件名取自 sse_events_v0.1.schema.json：status / tool_start / tool_end / token / done / error。
state来源事件UI 显示可做操作不可做

三条"UI 不能撒谎"的硬规则

  1. HTTP 连接关闭不等于终态。done / error 是唯一可信终态；连接断了只能进「结果待确认」，然后查 GET /chat/requests/{request_id}。
  2. 过程区只展示可核实动作。禁止"正在思考""AI 推理中"；tool_start 只代表"已被调度"，tool_end 才代表实际结束，失败不伪装成功。
  3. 认证失效后的流只返回通用认证错误，不再附带任何私有资源标识或内容；UI 直接替换为重新登录提示。

503MCP_UNAVAILABLE工具链路不可用 页内提示过程区对应步骤画为失败态；课表读取失败时用 S08 ② 文案「课表数据暂时无法读取，这不代表当天没有课。」重试（只读请求可直接重发）
503STORAGE_UNAVAILABLE存储依赖失败 页内提示读：按对应页面空/失败态呈现；写：结果待确认 + 「查询写入状态」，不转成 failed核实写入结果后再决定
504EXECUTION_TIMEOUT单轮 60 秒调度时限耗尽 页内提示 + 胶囊状态行胶囊「已超时」；「本轮处理超时，已停止。」若涉及保存 → 结果待确认 + 「查询写入状态」核实写入结果后再决定后续操作
504CALL_LIMIT_REACHED模型决策或工具调用预算耗尽 页内提示「本轮执行步骤已达上限，已停止。」保留已完成步骤的真实结果，不补一个假的完成态核实写入结果后再决定后续操作
500INTERNAL_ERROR未预期系统错误 整页或页内提示安全文案 + request_id（"请把编号提供给支持人员"）；不回传堆栈或数据库异常提供 request_id 给支持

6.1 同类码的补充说明（避免评审认为"漏了"）

异步文档任务的 task_error_code 不是 HTTP 错误

SRS §8 末尾明确：NO_TEXT_EXTRACTED、DOCUMENT_ENCRYPTED、PARSE_FAILED、EMBEDDING_FAILED、CLEANUP_FAILED、SERVICE_RESTARTED 是文件级任务错误码，其存在不意味着批次查询接口本身失败；200 返回的是可读任务状态，不是入库成功。它们的 UI 呈现是文件行上的失败胶囊 + 错误原因（S11 第 3、5 行），而不是页面级错误。

SERVICE_RESTARTED 的两个落点

① 对话侧：重启后无法恢复的 running 请求转为 failed，terminal_reason = SERVICE_RESTARTED，UI 呈现为失败态且说明"服务重启，本轮未完成"；② 文档侧：作为文件级任务错误码出现在失败胶囊上。两处都不推断计划是否已保存——那要查 WriteOperation。

6.2 content-spec 的五类"坏消息"必须一眼可分（映射复核）

对应 content-spec §4 评审问题 2；这是 IA 层面对"空结果 vs 失败"的最终对照。
坏消息屏幕块语义来源颜色语义可用动作

读取失败（课表）S08 ②依赖异常 503/504错误/警告「重试」

2 小时不续期、令牌仅内存、刷新重登、切号清空、清空对话不删计划、禁用即时失效

会话生命周期对 IA 的三个连带影响（评审时容易被追问）

  1. 没有"会话历史"页面：因为服务端历史是 P1（CHAT-03），IA 不预留入口，也不做灰置的"即将上线"占位。
  2. 没有跨标签页同步：内存态不共享，两个标签页是两个独立会话；同一份计划被两个标签页编辑时，靠 409 VERSION_CONFLICT 兜住，UI 保留未提交编辑（S09 文案）。
  3. 会话到点不弹窗拦截：不做"延长会话"的中间态，避免制造一个后端并不支持的续期承诺。
