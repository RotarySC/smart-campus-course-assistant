# 方向稿 · 内容与状态冻结清单 v1

本文件是三个视觉方向的**共同输入**。三个方向必须渲染**完全相同**的屏幕块、字段与文案；
差异只能体现在配色、字体、间距密度、圆角/阴影、布局结构与信息组织方式上。
这样评审者比较的是"视觉与密度"，而不是"内容多少"。

来源约束：本清单所有文案与状态均来自 `docs/校园课程智能助手_PRD_v0.1.md`、
`docs/校园课程智能助手_SRS_v0.1.md`、`docs/校园课程智能助手_HLD_v0.1.md`、
`docs/backend/openapi_v0.1.json`、`docs/backend/sse_events_v0.1.schema.json`。
不要发明新的业务状态；不要把 PRD 未承诺的能力（OCR、周课表、提醒、推送、服务端历史）画进任何方向。

## 0. 交付物形态（三个方向一致）

- 每个方向 = **1 个自包含 HTML 文件**（内联 `<style>`），双击即可在 Chrome/Edge 打开。
- **禁止任何外部请求**：不引 CDN、不引 webfont、不引图片文件、不引 JS 框架。
  图标一律**内联 SVG**（Lucide 风格 24×24 线性路径，`stroke-width: 1.75`，`fill: none`）。
- 允许极小量内联 `<script>`（仅用于标签页切换/折叠演示），不得依赖它才能看懂内容。
- 中文栈：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`
- 数字（时间、编号、日期）必须 `font-variant-numeric: tabular-nums`。
- 页面顶部必须有一段 `<section data-screen="S00">` 「设计理由与取舍」卡：
  一句话定位 / 适用场景 / 不适用场景 / 优点 / 代价。
- 页面底部必须有 `<section data-screen="S14">` 「设计 token 表」：把所有 CSS 自定义属性列成表格（名称、值、用途）。
- 每个屏幕块必须用 `<section data-screen="Sxx">` 包起来，并带可见的小标题，便于逐块比对。
- 顶部提供粘性屏幕导航（锚点到 S01…S13），方便评审快速跳转。
- 所有颜色必须来自文件顶部的 CSS 自定义属性（语义 token），**不允许在组件里写裸 hex**。

## 1. 通用交互与无障碍硬要求（每个方向都必须满足）

| 要求 | 具体做法 |
| --- | --- |
| 状态不只靠颜色 | 每个状态胶囊/徽标 = 图标 + 文字 + 颜色，三者齐备 |
| 焦点可见 | 所有可聚焦元素 `:focus-visible` 有 ≥2px 可见轮廓，且不被粘性栏遮挡 |
| 触控目标 | 主要操作 ≥44×44 CSS px；表格内次级图标按钮 ≥32×32 且带可访问名称 |
| 表单标签 | 一律可见 `<label>`；不得用 placeholder 当唯一标签；必填有文字标记「必填」 |
| 错误就近 | 字段错误显示在该字段下方，`aria-describedby` 关联；提交失败同时给出顶部错误摘要并把焦点移到摘要 |
| 危险操作 | 删除类操作用语义危险色 + 二次确认，且与主操作视觉分离 |
| 只读 vs 禁用 | 只读（如课程代码创建后不可改）与禁用必须视觉可区分：只读用灰底无边框样式并说明原因，禁用用降透明度 |
| 颜色对比 | 正文文字与背景 ≥4.5:1；大字号/非文字 UI ≥3:1 |
| 动效 | 只动 transform/opacity；提供 `@media (prefers-reduced-motion: reduce)` 降级 |
| 语义结构 | 标题层级不跳级；表格有 `<caption>` 与 `scope`；纯装饰图标 `aria-hidden="true"` |
| 长文本 | 文件名/课程名/ID 允许换行。**v1.1 修正**：`overflow-wrap: anywhere` 会降低 min-content 宽度，在 `table-layout: auto` 的表格单元格里会让该列被压到约 1 个字符宽。**表格单元格内一律用 `overflow-wrap: break-word`，并给该列设 `min-width`**；只有非表格的长文本容器才用 `anywhere`。任何情况下都不要对正文用 `word-break: break-all`。 |

## 2. 屏幕块清单（S01–S13，三个方向逐一对应）

### S01 登录
- 产品名：**校园课程智能助手**
- 副标题：查课表 · 问资料 · 存计划，一个入口
- 字段：账号（label「账号」，必填）、密码（label「密码」，必填，带显示/隐藏切换）
  - 密码「显示/隐藏切换」按钮 —— **内容契约（阶段 A 冻结；控件本身尚未实现）**：
    - **两态文案（逐字，唯一来源）**：密码当前被遮蔽（默认态）时按钮文字 = **显示密码**；
      密码当前明文可见时 = **隐藏密码**。不得只给图标不给文字，也不得简写成「显示」「隐藏」「眼睛」等。
    - **`aria-pressed` 语义** = 「密码当前是否已切换为明文可见」。默认 `aria-pressed="false"`（遮蔽，按钮名＝「显示密码」）；
      切换后 `aria-pressed="true"`（明文可见，按钮名＝「隐藏密码」）。两态文案与 `aria-pressed` **必须始终一致**，
      不得出现「按钮名＝显示密码但 `aria-pressed="true"`」这类自相矛盾的组合。
    - 形态：`<button type="button">` + `aria-controls` 指向密码 `<input>` 的 `id`；**必须**显式写 `type="button"`（否则会隐式提交表单）。
    - 行为：切换只把密码框的 `type` 在 `password` 与 `text` 之间改一次；**不得**清空已输入内容、不得移动焦点、不得触发校验。
    - 触控目标 ≥44×44 CSS px（见本文件 §1）；装饰图标（若有）一律 `aria-hidden="true"` + `focusable="false"`，可访问名只来自可见文字。
    - 登录失败文案与焦点规则不受本控件影响：仍用 **账号或密码不正确，请重试。**，并把焦点移回密码框。
    - 图标槽 token：本轮不新增（按钮有可见文字，可访问名已足够）；若日后改为纯图标按钮，须先补图标槽 token 并同步组件规格。
- 主按钮：**登录**
- 错误态（统一文案，不区分账号不存在/密码错误）：**账号或密码不正确，请重试。**
  行为说明：保留账号输入，清空密码，焦点回到密码框。
- 页脚提示：登录会话有效期 2 小时，到期后需要重新登录。
- 另需并排展示「账号被禁用」时的通用提示态：**当前账号不可用，请联系管理员。**

### S03 助手 · 执行中（过程反馈）
- 用户消息气泡：**明天有什么课？顺便看看实验课要准备什么。**

### S04 助手 · 有据回答 + 引用展开
- 回答正文（原文照抄，含引用标记）：

- 引用卡片（折叠 + 展开两种状态都要画）：
  - 折叠：**资料 1** · 数据结构实验指导书（2026 秋）.pdf · 第 12 页 · 「展开片段」
  - 展开后显示片段原文：实验前须完成预习并提交预习报告，报告不少于 500 字……
  - 必须体现：**引用只来自本次真实检索**；页码抽不到时只显示文件名与位置（给一个"无页码"的引用样例）
- 内容性质标签：**课程规定**（来自资料）与 **一般学习建议**（非资料依据）必须视觉区分、不得混排

### S05 助手 · 依据不足 / 检索失败（两态并列展示）
- 依据不足（检索成功但无足够依据）：**已检索共享资料，但没有找到足以回答这项要求的内容。**
  辅助动作：「换个问法」/「联系管理员补充材料」
- 检索失败（依赖异常）：**课程资料暂时无法查询，请稍后重试。** + 主按钮「重试」
- 全库为空：**管理员还没有上传可检索的课程资料。**
- 这三个态必须与 S04「有据」在**视觉上一眼可分**，且都不能用成功色。

## 4. 评审时要回答的问题（每个方向在 S00 里自答）

1. 这个方向让学生**第一次打开就知道能干什么**吗？
2. 空结果 / 读取失败 / 依据不足 / 检索失败 / 待确认 —— 这 5 个"坏消息"是否一眼可分？
3. 管理员在一屏里能否同时看清 5 种文档状态与整批发布规则？
4. 390px 下学生主流程（查课表 → 问资料 → 存计划）是否仍然顺畅？
5. 这个方向的代价是什么，什么情况下不该用它？
