S00

设计理由与取舍

方向定位 · 适用边界 · 对评审 5 问的自答

一句话定位：把校园里最常做、也最容易出错的三件事——查课表、按资料答问、把结论存成计划—— 放进一套正式、可核实、低学习成本的界面里，学生与管理员共用同一套视觉语言。

适用场景

  • · 学校官方系统或教务系统的延伸入口，与既有页面并排出现不违和。
  • · 用户以「办事」为目标：查一节实验课、确认预习要求、把结论存下来。
  • · 需要向老师、家长或评审解释「这条结论的依据在哪」的场合。
  • · 学生端与管理端由同一团队维护，复用同一套组件与状态语汇。

不适用场景

  • · 追求强品牌个性、营销感的 C 端产品：本方向刻意收敛色彩与动效。
  • · 需要在一屏同时监控几十个指标的数据看板：信息密度上限受 240px 侧栏约束。
  • · 面向低龄用户的轻量应用：冷灰中性色偏严肃，亲和力不足。
  • · 需要深色模式作为主场景的部署（本期未设计深色 token）。

代价

  • · 侧栏 240px + 右面板 320px 固定占位，1366px 下正文只剩约 700px，需要折叠把手兜底。
  • · 青色被严格限制为「有依据」语义，视觉上少了一个可用的强调色。
  • · 状态胶囊数量多（≥6 种语义），实现时若不统一组件会迅速失控。
  • · 严肃克制的观感在演示场景中不如鲜艳方案「抓眼球」。

优点

按可验证的行为排序，而非按观感排序
  • · 坏消息一眼可分：空结果（中性灰）／读取失败（危险红）／依据不足（警告橙）／检索失败（信息蓝）／待确认（靛蓝）使用五套互斥的颜色 + 图标 + 文案，任何一格都不与成功色混用。
  • · 依据可追溯：引用卡片用青绿左 3px 边框 + 「资料 n」编号贯穿正文标记，青色在全站只承担这一个含义。
  • · 低学习成本：学生端与管理端复用同一侧栏、工具条、表格与状态胶囊，管理员无需学第二套界面。
  • · 无障碍可核验：正文对比度 ≥4.5:1，焦点轮廓 3px 且带 offset，所有状态都是「图标 + 文字 + 颜色」三重表达。

对评审 5 问的自答

逐条可核验
  1. 1. 第一次打开就知道能干什么？ 是。登录后默认进入 S02：标题「你好，我是校园课程助手」+ 一句能力说明 + 三个可点击示例入口；示例只填入输入框，不自动提交，用户始终掌握提交权。
  2. 2. 五种坏消息一眼可分？ 见下方 S00 对比条，以及 S05 / S08 的并置展示。
  3. 3. 管理员一屏看清 5 种文档状态与整批规则？ S11 用一张批次卡承载「整批可见或整批不可见」规则，5 个文件行在 1366px 内全部竖排可见，无需横向滚动。
  4. 4. 390px 下主流程是否顺畅？ S13 给出三个真实 390×844 模拟框：助手输入吸底、过程区折叠为一行、示例入口横滑；课表改卡片式且无横向滚动。
  5. 5. 代价是什么？ 见上方「代价」与文末 S14 之后的取舍总结。

五种坏消息的视觉编码

颜色互斥 + 图标不同 + 文案不同，缺一即视为不通过
空结果

查询成功、确实没有记录。中性灰，不用错误色。

读取失败

服务异常，不代表没有数据。危险色 + 警告三角。

依据不足

检索成功但没有可支撑结论的片段。警告橙。

检索失败

依赖服务不可用，可重试。信息蓝，与「依据不足」严格区分。

待确认

写入结果未知，先查状态再决定。靛蓝，禁止用成功色。

无障碍落点（可逐条核验）

1. 可见 label：S01/S02/S09/S10/S11/S12 的所有输入控件都有可见 <label for>，必填以文字「必填」标记，占位符从不作为唯一标签。

2. :focus-visible：全站 3px 实心轮廓 + 2px offset，粘性栏与抽屉用 offset 保证轮廓不被裁切（见页首 skip 链接，按 Tab 即可看到）。

3. 状态三重表达：所有胶囊 = 内联 SVG 图标 + 文字 + 语义色，去掉颜色仍可读（如「完成 · 2 条记录」「删除失败」「依据不足」）。

4. 触控目标：主要按钮 44px 高；表格内图标按钮 32×32 且带 aria-label。

5. 就近错误 + 摘要：字段错误在字段下方并以 aria-describedby 关联；S09 给出顶部摘要并可聚焦。

6. 动效降级：仅旋转与轻微位移，prefers-reduced-motion: reduce 下全部关闭。

本方向刻意不做的事

  • · 不引入任何 CDN、webfont、位图或 JS 框架：图标全部内联 SVG（24×24，stroke-width 1.75，fill: none）。
  • · 不使用 emoji 充当图标。
  • · 不画 PRD 未承诺的入口：无选课、成绩、考勤、作业提交、提醒推送、OCR、周次节次、教务同步、跨设备历史、社交评论。
  • · 不把「正在思考 / 模型推理」写成过程状态。
  • · 不把「空结果」与「读取失败」合并成同一种视觉。
  • · 不出现真实学生数据、真实学校名或教师姓名；示例统一为虚构的「计算机学院」「主楼 A-305」「文科楼 B-102」。
总结

方向 A 的取舍

优点 / 代价 / 不适用场景

优点

  • 坏消息不会互相冒充。空结果、读取失败、依据不足、检索失败、待确认分别用中性灰 / 危险红 / 警告橙 / 信息蓝 / 靛蓝 + 五个不同图标 + 五套不同动作，且都不使用成功色。
  • 依据一眼可追。青绿只承担「有依据」一个含义：正文引用标记 ↔ 引用卡编号 ↔ 右面板引用列表三段一一对应，页码抽不到时明确写「位置未抽取」。
  • 学生与管理员一套语言。同一侧栏骨架、同一状态胶囊、同一表格与表单规范，管理员不需要学第二套界面，评审也不需要两套标准。
  • 无障碍是结构性的，不是补丁。对比度、焦点轮廓、label、32/44px 触控目标、reduced-motion 都写在 token 与基类里，新页面默认继承。
  • 实现成本低、风险小。零外部请求、零框架、纯 CSS + 极少内联脚本，直接映射到 Vue 组件与 FastAPI 接口字段，评审结论可以立刻进入开发。

代价

  • 横向空间被两侧固定栏吃掉。240px + 320px 固定占位后，1366px 下对话正文只剩约 700px；虽然给了折叠把手，但默认状态仍需要一次点击才能读到更宽的正文。
  • 可用强调色被语义挤占。青绿锁定为「有依据」，品牌色又要留给主操作，导致「进行中」只能用靛蓝浅底表达，与选中态容易混淆，实现时必须严格区分底色深浅。
  • 状态胶囊有 7 种变体。没有组件化约束时极易失控；必须先落一个 StatusPill 组件（variant + icon + label 三参数），否则后续页面会各自造轮子。
  • 情绪偏冷。冷灰中性 + 深靛蓝在演示、拉新或学生自愿使用的场景里不如鲜艳方案有吸引力；这是刻意的取舍，用于换取「可信」。
  • 窄屏需要两套排布。390px 下侧栏变抽屉、右面板变底部抽屉、表格需横向滚动，等于多维护一份响应式规则；收益是主流程不塌。

不适用场景

  • 需要强品牌个性的对外产品。本方向主动收敛色彩、阴影与动效，放到营销页或消费级产品里会显得过于行政化。
  • 高密度监控型后台。单屏需要同时观察几十个指标时，240px 侧栏 + 大留白卡片会降低单屏信息量，应改用紧凑型布局。
  • 以深色模式为主场景的部署。本方向只设计了浅色 token，深色需要重新校准整套语义色与对比度。
  • 面向低龄或轻娱乐用户。严肃的冷灰与蓝比暖色方案亲和力低，若目标用户对「像官方系统」有抵触，应选更轻的方向。
  • 需要一屏完成跨模块操作的高强度场景。本方向让学生与管理员共用骨架，但两条业务线仍各自独立成页，不做同屏混合工作台。
