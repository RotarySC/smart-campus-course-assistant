## 2. 总体描述

### 2.1 产品边界

系统提供 Web 客户端、业务服务、AI 编排与 MCP 工具服务、关系数据存储及文档检索能力。外部依赖为大模型服务、Embedding 服务、浏览器和部署环境。

本期覆盖账号与角色、课程维护、课表维护及个人查询、共享资料入库与检索问答、临时多轮对话、个人学习计划、审计和基本运行统计。

本期不覆盖选课、成绩、考勤、作业提交、自动排课、教师协作、支付会员、多组织租户、OCR、周次与节次排课、教务同步、服务端长期会话历史或消息提醒。管理式文档版本列表为 P1；重建所必需的内部版本切换属于 P0 一致性要求。

### 2.2 系统上下文

~~~mermaid

    WEB --> API[业务服务与 AI 编排]

    API --> MCP[MCP 工具服务]
    MCP --> DB
    API --> ING[文档处理任务]

    ING --> EMB[外部向量化服务]
    MCP --> EMB
~~~

### 2.4 环境与依赖约束

- PRD 的兼容路线为 Vue Web 客户端、FastAPI 业务服务、MySQL、独立 MCP 服务及文档向量检索；具体框架版本由详细设计锁定并复核兼容性。
- 试点至少需要一个可用的工具调用模型、一个可用的 Embedding 服务以及可恢复的业务数据和文档存储。
- 学校时区由服务端统一配置，默认 Asia/Shanghai。服务端时间为日期解析的可信来源。
- 文档来源与外发处理范围须经试点负责方确认；本期共享库不接收需要班级、教师或个人授权的资料。
- 外部 AI 故障时，普通课表、计划和管理页面仍应可使用。

### 3.1 本稿采用的细化决策

| 决策 | 本稿规则 | 与 PRD 的关系 |
| --- | --- | --- |
| DEC-01 临时上下文 | 浏览器内存保存当前会话；刷新、退出、关闭页面后不保证恢复 | 明确 CHAT-03 |
| DEC-02 短期草稿 | 服务端可保存带归属的短期草稿与写入许可，不保存长期完整会话；草稿过期或服务重启可失效 | 支持 PLAN-02 的版本绑定 |

| DEC-04 流式终态 | 成功／停止用 done 结束，失败用 error 结束；同一连接最多一个终态事件 | 明确 CHAT-02 |

| DEC-08 文档删除竞态 | 删除提交后，新检索和引用展开均排除该资料；已取回、尚未输出的片段在输出前复查 | 明确 DOC-03 的可见性 |

## 4. 功能需求

各需求采用“触发／系统行为／异常与验收”表述。第 11 节提供独立验收场景，第 12 节提供追踪矩阵。

### 4.1 账号与权限

**FR-AUTH-001 认证**

收到账号密码登录请求时，系统应验证凭据和账号状态。有效学生或管理员登录后获得限时会话及对应菜单；账号不存在、密码错误或禁用时均不得建立会话，对外使用统一认证失败文案。密码不得明文保存或回传，日志不得记录凭据。

**FR-AUTH-002 登出与失效**

登出应撤销当前会话并清除浏览器临时身份、问答和草稿引用。过期或撤销令牌再次访问应失败。禁用账号应撤销该账号全部会话；业务接口和工具入口每次执行前检查启用状态。流式连接发送后续业务事件前复查会话是否有效，失效后只能终止，不继续发送私有结果。

**FR-AUTH-003 学生账号维护**

管理员应能创建学生账号、查询学生列表、修改显示名、启用或禁用学生。账号唯一且不能通过本期接口修改；账号角色不能由普通管理请求设置。初始管理员通过部署配置创建。本期不提供自助注册、删除用户或授予管理员的界面。

**FR-AUTH-004 服务端授权**

所有受保护接口应校验身份、角色和资源归属；MCP 工具必须独立校验同一身份链。未认证返回 401；已认证但无管理角色返回 403；请求他人的私有资源按不存在返回 404，不透露目标是否存在。额外提交 user_id、role 或系统保留字段应被拒绝，不得忽略后用于执行。

### 4.2 课程与课表

**FR-COURSE-001 课程维护**

管理员应能按代码或名称查询课程，创建课程，修改名称和简介，启用或停用课程。代码与名称必填，代码在单组织内唯一。首期代码创建后不修改。停用课程不能用于新增课表；既有课表仍可读取。

**FR-COURSE-002 引用完整性**

本期不暴露课程物理删除接口。有课表引用的课程不得被后台任务或运维普通操作删除。已有计划是保存时的独立内容快照，课程更名或停用不得自动重写计划正文。

**FR-SCH-001 本人课表查询**

学生或管理员进入“我的课表”时，默认查询学校时区的当日记录。支持给定起止日期，跨度不超过配置上限，按日期、开始时间、记录 ID 升序返回。两端均未给出时为今天；只提供一端时视为查询该单日；两端给出时开始日期不得晚于结束日期。客户端不得指定本人查询的目标用户。查询成功无记录时返回空集合；数据源失败应返回错误而非空集合。

**FR-SCH-002 相对日期**

助手应以本轮请求被服务端接受的时刻为锚点，结合学校时区解析“今天”“明天”“下周一”；同轮跨午夜不改变已经解析的日期。采用周一为每周起点，“下周一”为当前自然周之后一周的周一。解析结果必须在答案中显示为完整日期。日期缺失或存在无法唯一解释的表达时应补问，不能任意选择。

**FR-SCH-003 管理课表**

管理员应能按学生及日期查询、新增、修改和删除具体课表记录。学生、课程、日期、开始及结束时间必填；课程和学生须有效，结束时间大于开始时间且同日。用户归属创建后不可更改，转移安排使用删除和新建完成。

**FR-SCH-004 重复、重叠与删除**

同一学生、课程、日期、起止时间完全相同的记录不得重复保存。相同学生同日时间段存在交集时，首次请求返回冲突及允许查看的重叠记录；管理员明确确认并填写原因后可以继续，保存时应重新检查。课表修改和删除使用记录版本检测并发冲突。删除前界面应展示学生、课程和时间，提交后应审计。

### 4.3 文档与入库

**FR-DOC-001 文件校验**

仅管理员可以提交批次上传。系统应同时校验文件数、单文件与总字节数、后缀及实际格式，允许 TXT、MD、含文本层 PDF 和 DOCX。禁止使用客户端文件名拼接存储路径；每份文件分配内部标识。任一上传校验失败时，整批不得发布。

**FR-DOC-002 解析与可解释失败**

接受批次后应异步执行抽取、分块和向量化，管理员可查询状态。空文本、纯扫描件、格式损坏、加密且无法读取的文档应失败并说明原因，不以空片段成功入库。系统应区分无文字与 Embedding、存储或处理服务故障。本期不 OCR。

**FR-DOC-003 批次可见性**

同批新增文件只有在全部完成解析、向量化及元数据确认后才可一起对检索可见。任一文件失败则该批全部不发布，并进入补偿清理。其他已发布批次保持可用。发布和清理动作应支持重试，服务重启后不得发布半批数据。

**FR-DOC-004 管理预览与命名**

管理员应能预览抽取的纯文本；预览不可用须显示原因。文件同名不自动覆盖，返回提示并要求选择取消或作为独立文档继续。列表应展示原名、类型、大小、上传时间、批次、处理状态和错误原因，不展示磁盘路径。

**FR-DOC-005 重建**

同一文档一次仅允许一个重建或删除变更。重建生成新内部版本；成功后以单个发布切换点替代旧版本，失败时保留旧可用版本。重建不得改变原文档身份，不得把新旧版本片段混合为同一次检索结果。公开版本管理页面不在本期范围内。

**FR-DOC-006 删除与引用失效**

管理员确认删除后，系统应首先提交不可见标记，再异步清理文件、文本和向量。新检索及引用展开立即排除该文档；检索后尚未交给模型或用户的片段应重新检查有效性，必要时移除并说明依据已变化。清理成功才报告完成，失败提供重试与可追踪原因。已经发送的答案文字不承诺撤回。

**FR-DOC-007 恢复与补偿**

未完成批次、重建、删除和清理任务应有持久状态、执行租约或等效防重机制。进程重启后扫描并恢复或标记为可重试，重复执行不得重复发布、删除其他文档或使已删资料重新可见。正常依赖下清理应满足第 3 节目标，超过目标记录告警。

### 4.4 对话与 Agent

**FR-CHAT-001 提交与并发**

当前问题去空白后非空且在长度上限内才接受请求。客户端生成唯一 client_request_id；同一用户与会话在同一时间最多一轮执行。首次请求可不传 conversation_id，由服务端分配并绑定当前用户与认证会话；后续请求只能使用本会话下的标识。重复请求标识不重复调用模型；已有运行轮次时返回冲突，指向可查询状态。示例入口只填写文本，不自动提交。

**FR-CHAT-002 临时上下文与可信度**

每次请求仅接受 user／assistant 类型的历史问答，拒绝 system、tool 或任意客户端工具结果。服务端追加真正的系统指令与认证上下文，验证历史长度并按模型预算保留最近的完整问答对。若发生截断，应发送可见状态提示；被移除内容不可继续被当作指代依据。

历史 assistant 消息、客户端草稿标识及“之前已授权”的文本均不能证明权限或数据真实性。当前业务事实应通过工具重查，当前资料依据应重新检索。账号切换、退出或清空后应清除临时上下文；清空前说明不会删除已保存计划。

**FR-CHAT-003 流式展示**

系统应按第 6 节发送结构化状态、工具动作、正文与终态事件。工具开始和结束一一关联，实际失败不得显示为成功。界面仅展示任务阶段和实际工具动作，不展示模型内部推理。Markdown 必须安全渲染。

**FR-CHAT-004 执行限制与停止**

每轮应分别统计模型决策次数、工具调用数和总时长，任一上限达到即停止后续调度，记录原因并结束本轮。用户可通过停止接口提出取消；取消在下一个可中止边界生效，不保证第三方已发出的请求立即停止计费或返回。取消与超时均不回滚已经提交成功的计划。

**FR-CHAT-005 断线与状态查询**

网络断开时，客户端应将显示状态置为“结果待确认”，不得直接认定执行失败或未写入。服务端不得通过自动重放 SSE 来重新执行工具。应提供仅含执行元数据和已确认写入引用的状态查询接口；当前用户可据此找到已保存计划。只读失败可以用新请求重试，写操作须先按原操作标识核实结果。

**FR-CHAT-006 多步任务**

对“查课表、依据资料生成计划并保存”的请求，系统应按数据依赖依次执行。必需的课表或资料步骤失败、无足够依据或存在未消除歧义时，不得自动保存一份宣称已参考这些输入的计划；可说明缺口并等待用户同意使用一般建议。

### 4.5 检索问答

**FR-QA-001 先检索后归因**

涉及课程规定、实验要求、评分规则等资料事实时，系统应先执行共享知识库检索，且只使用已发布、未删除、当前有效版本的片段。仅有文本相似度不足以视为支持结论；答案必须能够逐项对应到有效来源。

**FR-QA-002 引用**

系统应从实际检索片段构建引用清单，包含稳定来源标识、文档名、片段和可用位置。模型生成的文件名、引用序号或链接不得直接成为可信来源。模型输出中不存在于清单的引用标记应被过滤并标注无法验证。无法可靠抽取页码时不展示页码。

**FR-QA-003 无结果与失败**

有效检索但依据不足时，应说明没有找到足够资料，不推断课程没有这项规定。检索或外部依赖失败时，应说明暂时无法查询，不声称已查阅或没有资料。普通学习建议允许提供，但应清晰标为建议，不能混入资料规定。

**FR-QA-004 歧义与冲突**

无法区分同名课程时应先补问。不同资料要求冲突时应并列展示依据与冲突点，不擅自判定哪份生效。全库为空时提示管理员尚未提供材料。无明确课程标签的 MVP 不提供强课程级过滤保证。

### 4.6 学习计划

**FR-PLAN-001 个人管理**

登录用户应能手动创建、分页查询、按标题筛选、查看、编辑和删除本人的计划。标题和正文必填，目标选填；日期可同时不填，若填写则须起止完整且有序。列表按更新时间和 ID 倒序。更新、删除使用资源版本防止覆盖其他标签页的新内容。

**FR-PLAN-002 生成草稿**

仅要求规划时应生成标为“未保存”的草稿，包含标题、目标、可选起止日期、正文、依据类型与所用引用。关键条件缺失应补问；非关键假设应明示。创建草稿不产生 StudyPlan 记录。

短期草稿须由服务端分配 draft_id 和递增版本并绑定当前身份与会话。草稿过期或不可恢复时应明确提示重新生成，不以客户端传回的 assistant 文本重建可信草稿。

**FR-PLAN-003 保存授权**

以下入口可授予保存许可：当前用户提交手动创建表单、点击指定草稿版本的保存按钮，或当前用户直接发出可确定的生成并保存指令。许可由应用层生成并绑定用户、会话、请求、草稿版本与内容摘要，工具和模型不能自行创建或修改许可。

应用层应拒绝否定、引用材料、历史转述及指代歧义产生的写入意图；仅靠模型返回 save=true 不构成授权。对于无法确定的表达，应保持预览并提供保存按钮。明确要求生成并保存且内容生成完成时可直接保存，不增加强制二次确认。

**FR-PLAN-004 幂等与次数上限**

每个逻辑创建动作应分配 operation_id，页面保存与工具调用共用该值。系统以持久唯一约束保证同一用户、同一操作只对应一个创建结果，并限制同一助手请求最多成功创建一份计划。

相同 operation_id 与相同内容重试，返回同一 plan_id；相同操作标识配不同内容，返回冲突，不覆盖旧内容。模型重新生成操作标识不能绕过同轮上限。计划记录、操作结果和许可消费应在同一可靠提交边界完成。

**FR-PLAN-005 结果核实与失败恢复**

只有数据库确认提交后才显示“保存成功”，并提供 plan_id 和详情入口。明确失败则保留仍有效的草稿；提交结果未知时应查询持久操作记录。处理中不得再提交新的逻辑保存，已成功记录应直接复用。草稿修改或重新生成后旧许可失效；新版本保存属于新的明确操作，但不能绕过助手同轮创建上限。

### 4.7 工具边界、审计与统计

**FR-GUARD-001 工具白名单和身份**

通用助手仅可使用查询本人课表、检索共享资料、保存本人计划三类工具。工具执行身份来自受验证的认证上下文；工具业务参数不得包含可替换归属的目标用户。管理课表和学生维护必须经独立管理接口，不能借通用助手调用。

**FR-GUARD-002 外部内容与参数**

资料、模型输出和历史消息均按不可信内容处理，不能更改系统指令、权限或保存许可。工具参数严格进行结构、类型、长度和业务校验；系统保留字段及未声明字段拒绝。工具返回只包含所需业务结果，不包含令牌、密钥、磁盘路径或数据库连接信息。

**FR-OPS-001 审计**

用户管理、课程与课表维护、文档变更、计划写入及工具执行应记录操作者、对象标识、动作、时间、结果、request_id 和耗时。权限拒绝、同轮重复保存拦截及清理超时应可追踪。日志默认不复制问题、课表、计划、资料正文或凭据。

**FR-OPS-002 基本运行统计**

系统应记录请求提交、工具结束、回答终止、引用展开、草稿形成、计划写入及批次结束事件。计划保存指标只在数据库确认提交后记成功，幂等命中不重复计为新建。统计需区分空结果、服务失败、用户取消、限额终止和认证失效。本期不要求独立可视化看板。

## 5. 数据需求

### 5.1 通用数据规则

**DR-001 标识与编码：**API 中资源标识采用不透明字符串，客户端不得依赖其数字大小或编码规则；JSON 与文本使用 UTF-8。字符串上限按 Unicode 码点计数，禁止隐式截断。用户标识由认证上下文确定。

**DR-002 日期与时间：**课表使用学校本地日期及同日时间，时区随响应返回；业务审计及通用时间戳存储为 UTC，API 使用带时区的 ISO 8601 时间。计划覆盖日期为日期值，不按浏览器时区移动。

**DR-003 并发与唯一性：**可编辑业务记录带 version，更新必须携带 expected_version。版本不匹配返回 409，不静默覆盖。账号、课程代码及操作幂等键均建立数据库层或同等强度唯一性保障。

**DR-004 私有数据：**StudyPlan、PlanDraft、SaveGrant、WriteOperation 和 ChatRequest 均关联 user_id。所有查询先限定归属再取记录，不能先返回数据再由前端判断。

**DR-005 列表：**列表响应包含 items、page、page_size、total，空列表使用 items=[]。过滤条件须有白名单和上限；排序包含稳定的 ID 次序，不能拼接任意客户端字段为 SQL。

### 5.2 逻辑数据字典

字段类型为逻辑类型，非数据库建表脚本。主键、审计及状态字段由服务端维护。

| 对象 | 核心字段／约束 |
| --- | --- |
| User | id；account 3–64 字符，去首尾空白、大小写不敏感唯一；display_name 1–50；password_hash；role=student/admin；enabled；auth_version；version；created_at/updated_at |
| AuthSession | id；user_id；到期时间；撤销时间；令牌关联标识。登出可撤销单会话，禁用可使全部会话失效 |
| Course | id；code 1–32，去空白后大小写不敏感唯一；name 1–100；description ≤2,000；enabled；version；时间戳 |
| Schedule | id；user_id；course_id；class_date；start_time/end_time，精度分钟且 start<end；location ≤200；冲突确认原因 ≤500；version；时间戳 |
| DocumentBatch | id；上传人；state；发布状态；文件数；总字节；错误码；任务重试信息；时间戳。批次内新增资料统一发布 |
| Document | id；batch_id；original_name ≤255；file_type；byte_size；内部存储引用；active_version；visibility；processing_state；deleted_at；version |

| StudyPlan | id；user_id；title 1–100；goal ≤500 可空；start_date/end_date 同空或完整；content 1–10,000；source=manual/assistant；依据类型；version；创建及更新时间 |

| SaveGrant | grant_id；user_id；request_id；draft_id/version；内容摘要；operation_id；到期时间；状态。仅服务端创建，消费后不可用于其他内容 |
| WriteOperation | user_id；operation_id；来源；关联 request_id 可空；内容摘要；state；plan_id 可空；错误码；时间戳。用户与操作标识唯一 |

### 5.3 保留与删除

- 计划删除后个人界面与读取接口均不可再见；若保留回收或审计记录，只保留必要元数据，禁止学生或管理员通过旧链接恢复正文。
- 文档以 visibility 控制可检索性，后台清理包括原文件、抽取文本、片段、向量及临时版本；重试不恢复其可见性。
- 草稿过期后应被清理；用户退出或账号切换后浏览器不继续持有可展示的草稿正文。
- 幂等键摘要与最终结果不得在普通请求重试可能发生时被提前删除。本期默认随计划保留；计划删除后保留“已创建后删除”的操作墓碑，旧请求不重新创建计划。其长期清理政策为 TBD-06。
- 审计记录不替代业务备份。备份中的删除数据随批准的备份周期淘汰，恢复时应重放有效删除标记，避免删除对象重新对用户可见。

## 6. 外部接口要求

本节路径与消息体为联调草案。IF 编号和业务语义作为评审对象，最终发布 OpenAPI 应与本文保持同步。

### 6.1 IF-001 通用 HTTP 契约

- 普通接口基路径为 /api/v1，使用 JSON；上传使用 multipart/form-data，流式对话使用 text/event-stream。
- 除登录外，业务接口使用受保护认证会话。采用 Bearer 令牌时由 Authorization 头传递，不放入 URL。业务服务到 MCP 的身份也不得暴露在模型可见参数中。
- 成功结果示例见下；创建为 201，异步任务为 202，普通成功为 200。删除返回确认结果及删除状态，不使用没有含义的空成功。
- 失败包含稳定错误码、面向用户的安全文案及 request_id，不回传堆栈或数据库异常。字段校验错误可包含 field_errors。
- 客户端请求中的系统保留字段及未声明字段按 422 拒绝。仅管理课表和用户接口允许规范声明的目标 student_id。
- 创建计划必须有 Idempotency-Key；更新和删除可编辑资源必须携带 expected_version。
- 服务端生成 request_id；客户端 client_request_id 仅用于调用去重，不能用于取得其他用户请求状态。

~~~json
{
  "request_id": "req_example",
  "data": {
    "items": [],
    "page": 1,
    "page_size": 20,
    "total": 0
  }
}
~~~

~~~json
{
  "request_id": "req_example",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "请检查输入内容",
    "field_errors": [
      {"field": "end_time", "reason": "必须晚于开始时间"}
    ]
  }
}
~~~

| POST /auth/logout | 当前会话 | 无 | 当前会话撤销结果 |

### 6.3 IF-003 课表接口

| 方法与路径 | 权限 | 主要字段 | 成功输出／约束 |
| --- | --- | --- | --- |
| GET /me/schedules | 登录 | from_date、to_date；默认均为今天 | 本人记录、查询日期、学校时区；支持分页 |
| GET /admin/schedules | 管理员 | student_id、起止日期、分页 | 目标学生记录 |
| POST /admin/schedules | 管理员 | student_id、course_id、日期、起止时间、地点；可选冲突确认及原因 | 新记录；精确重复始终拒绝 |
| PATCH /admin/schedules/{id} | 管理员 | 课程、日期、起止时间、地点、expected_version；可选冲突确认 | 更新结果；归属学生不可修改 |
| DELETE /admin/schedules/{id} | 管理员 | expected_version | 删除结果与审计标识 |

重叠响应为 409 SCHEDULE_OVERLAP，返回重叠记录摘要。后续覆盖请求需明确 overlap_acknowledged=true 且 reason 非空；服务端重查冲突，不能盲信首次查询快照。

### 6.4 IF-004 文档接口

| 方法与路径 | 权限 | 主要字段 | 成功输出／约束 |
| --- | --- | --- | --- |
| POST /admin/document-batches | 管理员 | files[]；同名文档继续上传标记 | 202 batch_id 和初始状态 |
| GET /admin/document-batches/{id} | 管理员 | 无 | 整批及逐文件进度、发布状态、错误原因 |
| GET /admin/documents | 管理员 | 分页、状态、名称 | 文档列表 |
| GET /admin/documents/{id}/text | 管理员 | 页码或偏移、长度上限 | 抽取文本的分页片段 |
| POST /admin/documents/{id}/rebuild | 管理员 | expected_version、操作去重键 | 202 任务标识；并发变更返回 409 |
| DELETE /admin/documents/{id} | 管理员 | expected_version | 202 已不可见、清理任务状态 |
| POST /admin/documents/{id}/cleanup-retry | 管理员 | 操作去重键 | 重试清理状态；不能使文档恢复可见 |
| GET /citations/{reference_id} | 登录 | 无 | 有效引用片段；引用失效返回 410 |

文档、批次与引用标识不得包含可由浏览器直接解析的磁盘路径。引用接口每次验证文档仍可共享且版本有效，不能凭旧 reference_id 绕过删除。

### 6.5 IF-005 计划与草稿接口

| 方法与路径 | 权限 | 主要字段 | 成功输出／约束 |
| --- | --- | --- | --- |
| GET /me/plans | 登录 | 分页、标题关键字 | 个人计划列表 |
| GET /me/plans/{id} | 本人 | 无 | 完整计划与 version |
| POST /me/plans | 登录 | 标题、目标、日期、正文；Idempotency-Key | 手动计划；身份与 source 由服务端固定 |
| PATCH /me/plans/{id} | 本人 | 计划字段、expected_version | 更新计划，不创建第二份 |
| DELETE /me/plans/{id} | 本人 | expected_version | 删除结果；旧幂等操作保留墓碑 |
| GET /me/drafts/{draft_id} | 本人且当前会话 | 无 | 有效草稿及版本；过期返回 410 |
| PATCH /me/drafts/{draft_id} | 本人且当前会话 | 计划字段、expected_draft_version | 新草稿版本；旧许可失效，不写入个人计划 |
| POST /me/drafts/{draft_id}/save | 本人且当前会话 | draft_version、Idempotency-Key | 针对该版本授予许可并执行保存，返回 plan_id |

手动创建不接受 source=assistant、user_id 或 save_grant。草稿保存不接受客户端同时改写正文；编辑草稿时须形成新版本并重新触发保存入口。

### 6.6 IF-006 对话接口与生命周期

| 方法与路径 | 主要字段 | 说明 |
| --- | --- | --- |
| POST /chat/stream | client_request_id、conversation_id、message、history[] | 成功建立流后发送 SSE；本轮保存意图仅从当前 message 的可信用户指令识别 |
| GET /chat/requests/{request_id} | 无 | 返回本人执行元数据、状态、终止原因和已确认计划引用 |
| POST /chat/requests/{request_id}/cancel | 无 | 幂等提出停止；返回取消是否已接受及当前状态 |

浏览器采用支持认证头及 POST 流式读取的请求方式；不要求将凭据放入原生 EventSource 的 URL。客户端中止连接与取消接口是不同动作，断线不等价于执行已取消。

初始认证或参数错误在建立流之前以普通 HTTP 错误返回。建立流之后发生的错误通过 error 事件返回，不能在响应中途改写 HTTP 状态码。

### 6.7 IF-007 SSE 事件

每个业务事件应有 id、event 和 JSON data。id 在单个 request_id 内单调递增；data 至少含 request_id、seq、timestamp；首次 status 还应返回服务端确认的 conversation_id。seq 与事件 id 表示相同排序。

| 事件 | 附加字段 | 语义 |
| --- | --- | --- |
| status | code、message、可选 draft_id/version | 已接受、正在处理、上下文截断、草稿可用等 |
| tool_start | tool_call_id、tool_name、display_name | 工具已被调度；不回传身份凭据 |
| tool_end | tool_call_id、success、result_status、可选 plan_id | 实际工具结束；失败不伪装成功 |
| token | text_delta、answer_block_id | 用户可见正文增量，不含内部推理 |
| done | state=succeeded/cancelled、可选原因、citations[]、plan_id、operation_id | 成功或取消的唯一终态 |
| error | code、message、state=failed、可选已确认 plan_id/operation_id | 失败的唯一终态 |

~~~text
id: 3
event: tool_end
data: {"request_id":"req_example","seq":3,"timestamp":"2026-10-21T02:00:00Z","tool_call_id":"call_1","success":true,"result_status":"empty"}

id: 4
event: done
data: {"request_id":"req_example","seq":4,"timestamp":"2026-10-21T02:00:01Z","state":"succeeded","citations":[]}
~~~

同一已建立连接最多发送一个 done 或 error，发送后关闭。断线可能收不到终态，真实状态通过状态接口查询。客户端以 request_id+seq 去重；Last-Event-ID 不触发工具重放，本期不承诺断线续传正文。

引用列表可在 done 中返回，正文流中的标记在校验前仅显示为待验证状态。错误终止但已有计划提交且会话仍有效时，应携带可核实的计划引用，避免用户误判未保存。若终止由认证过期、撤销或账号禁用引起，事件只返回通用认证错误，不再附带私有资源标识或内容。

### 6.8 IF-008 MCP 工具契约

工具服务仅允许受认证、具备当前用户上下文的业务服务连接，不能公开匿名调用。工具业务输入使用严格 schema；身份与保存许可经可信执行上下文传递，不作为模型可任意填写的参数。

| 工具 | 模型可见业务输入 | 服务端校验 | 标准结果 |
| --- | --- | --- | --- |
| get_my_schedule | from_date、to_date | 认证身份、启用状态、日期跨度 | status=ok/empty；查询范围、时区、items[] |
| search_course_docs | query | 身份、长度、有效发布资料过滤 | status=ok/empty；chunks[]、来源清单 |
| save_study_plan | draft_id、draft_version | 草稿归属、许可、内容摘要、操作标识、同轮上限 | status=created/existing；plan_id、operation_id |

技术或认证错误使用统一的错误结构及错误码，不能用 items=[] 或 chunks=[] 表示。save_study_plan 不接受任意 user_id 或未经许可的计划正文。工具操作标识来自服务端请求上下文，不能由模型更换。

### 6.9 IF-009 外部模型与向量化服务

- 服务端持有密钥并管理超时、并发、输入预算及可观测调用标识；密钥不得到达浏览器、模型提示或公开日志。
- 仅发送完成任务必需的内容：模型接收当前输入、受控上下文、必要工具结果；Embedding 接收检索文本或待向量化片段。
- 供应商错误应映射为本系统稳定错误码，不直接暴露内部响应。
- 外部调用重试次数计入请求时长及调用预算；模型重试不能导致写入工具再次执行出新的业务结果。
- 更换模型或 Embedding 模型须重新执行适用评测；向量空间变化时，不能在同一有效索引中混用不兼容向量。

## 7. 状态模型与一致性

### 7.1 对话请求

~~~mermaid
stateDiagram-v2
    [*] --> Accepted
    Accepted --> Running
    Accepted --> Cancelled
    Accepted --> Failed
    Running --> Succeeded
    Running --> Failed
    Running --> Cancelled
    Succeeded --> [*]
    Failed --> [*]
    Cancelled --> [*]
~~~

终态不可改写为另一终态。取消先设置 cancel_requested，再由执行器在可中止边界提交 Cancelled；若完成先提交，则取消返回当前完成状态。服务重启后无法恢复的 Running 请求转为 Failed/SERVICE_RESTARTED；是否有计划已保存另查 WriteOperation，不从对话终态推断。

### 7.2 文档批次与版本

| 对象 | 状态或属性 | 转换与约束 |
| --- | --- | --- |
| 批次 | accepted → processing → published | 仅所有文件就绪后一次发布 |
| 批次失败分支 | processing → compensating → failed | 清理未完成保持 compensating 并标记超时，不伪报清理完成 |
| 内部版本 | staging → ready → active → retired | 新版完成后替代旧版；任一文档最多一个 active |
| 版本失败 | staging → failed | 保留已有 active，不发布失败版本 |
| 可见性 | unpublished/shared/removed | 检索须同时满足批次发布、shared、active 三个条件 |
| 删除任务 | pending → running → succeeded/failed | removed 标记不因清理失败反转；failed 可重试 |

重建时显示“可用，正在重建”，不能仅因 processing 标记使旧 active 版本不可查。学生界面只需要区分引用有效、过期或已删除，不展示后台全部内部状态。

### 7.3 草稿、许可与写入操作

- 草稿版本为不可变内容快照；修改创建新版本，旧版本许可不得继续消费。
- 许可为 issued → consumed，或 issued → expired/revoked；绑定操作成功后重复调用只能返回既有结果。
- 写入操作为 pending → succeeded 或 failed；计划删除后 succeeded 的对外查询结果标记为 deleted，不能重新执行创建。
- 提交异常导致结果未知时，对外显示 pending 或 recovering，并通过持久数据库状态核实。确认无提交且确为可重试错误时，允许同键重新领取执行权；不可通过新的键回避未确认的旧操作。
- 当取消与写入并发时，以事务提交点为界。已提交则保留计划；尚未开始写入或已确认回滚则不创建。状态响应应始终反映真实结果。

### 7.4 一致性不变量

| 编号 | 任意时刻均需满足的约束 |
| --- | --- |
| INV-01 | 个人课表与计划的读取／变更归属等于认证用户，管理课表显式例外且独立授权 |
| INV-02 | 同一用户、同一创建操作最多一份计划；同一助手请求最多成功创建一份 |
| INV-03 | 没有有效保存许可的助手请求产生零份持久计划 |
| INV-04 | 未发布、已删除、失败版本或非当前版本的片段不得进入新检索的有效结果 |
| INV-05 | 成功状态须对应实际成功提交；查询失败不得转换成业务空结果 |
| INV-06 | 模型、历史消息和上传资料不能自行改变角色、目标用户、工具白名单或许可 |
| INV-07 | 一个对话请求只有一个持久终态，计划写入状态独立可核实 |

## 8. 异常处理与错误码

**IF-010 错误语义：**同一种错误在普通 API、SSE 和 MCP 中使用相同业务 code。HTTP 状态只适用于建立流前及普通接口；流内通过 error 或 tool_end 的业务状态表达。

| HTTP | code | 条件 | 客户端行为 |
| --- | --- | --- | --- |
| 401 | AUTH_REQUIRED / SESSION_EXPIRED | 无有效会话、过期或撤销 | 停止后续请求，重新登录 |
| 403 | FORBIDDEN | 角色无权操作管理能力 | 返回可访问页面，不重试 |
| 404 | RESOURCE_NOT_FOUND | 不存在或不属于当前用户 | 不显示目标是否真实存在 |
| 409 | DUPLICATE_ACCOUNT / DUPLICATE_COURSE / DUPLICATE_SCHEDULE | 唯一键冲突 | 修改输入 |
| 409 | VERSION_CONFLICT | 更新版本不匹配 | 重新加载，保留未提交编辑供核对 |
| 409 | SCHEDULE_OVERLAP | 时间重叠未确认 | 展示冲突，管理员可说明后确认 |
| 409 | CHAT_IN_PROGRESS / REQUEST_ALREADY_EXISTS | 同会话运行或请求重复 | 查询原请求状态 |
| 409 | IDEMPOTENCY_CONFLICT / SAVE_LIMIT_REACHED | 同键异内容或同轮第二次创建 | 展示已有结果，不新建 |
| 409 | DOCUMENT_BUSY / DUPLICATE_FILENAME | 文档变更并行或同名待处理 | 等待，或明确按独立文档上传 |
| 410 | DRAFT_EXPIRED / CITATION_UNAVAILABLE | 临时内容或引用失效 | 重新生成或检索 |
| 413 | UPLOAD_TOO_LARGE | 单文件或整批超限 | 提示限额 |
| 415 | UNSUPPORTED_FILE_TYPE | 类型不受支持 | 选择允许文件 |
| 422 | VALIDATION_FAILED / SAVE_NOT_AUTHORIZED | 字段错误、日期错误、许可不成立 | 修正输入或展示未保存草稿 |
| 429 | CAPACITY_LIMITED | 达到部署并发保护上限 | 告知稍后重试，不自动重放写操作 |
| 503 | MODEL_UNAVAILABLE / RETRIEVAL_UNAVAILABLE / MCP_UNAVAILABLE / STORAGE_UNAVAILABLE | 依赖失败 | 提示具体能力暂不可用 |
| 504 | EXECUTION_TIMEOUT / CALL_LIMIT_REACHED | 时间或执行预算耗尽 | 核实写入结果后再决定后续操作 |
| 500 | INTERNAL_ERROR | 未预期系统错误 | 安全文案及 request_id，用于支持定位 |

异步文档任务还应提供 NO_TEXT_EXTRACTED、DOCUMENT_ENCRYPTED、PARSE_FAILED、EMBEDDING_FAILED、CLEANUP_FAILED、SERVICE_RESTARTED 等 task_error_code；其存在不意味着批次查询接口本身失败。200 返回的是可读任务状态，不是入库成功。

## 9. 非功能需求

### 9.1 测量负载与性能

以下为建议验收负载和目标，未经过实测：200 个学生、20 个在线用户、5 个并发助手请求、200 份已发布文档。文档平均体积、课表及计划总记录数、服务器规格、网络和模型配置在压测前冻结。

**NFR-PERF-001 普通接口：**上述负载下，普通读取服务端响应 P95≤1 秒。至少采集 1,000 次读取，分别报告成功率、P50/P95/P99，超时计入失败，不能从报告中剔除。

**NFR-PERF-002 流式延迟：**助手首状态事件端到端 P95≤1 秒；首段实质回答 P95≤10 秒，分别报告不调工具、查课表和检索资料场景。至少执行 100 个有效请求，每类至少 20 个。单独报告超时率，成功请求延迟达标不能掩盖大量失败。

**NFR-PERF-003 入库：**1 MiB 内纯文本单文件的入库 P95≤60 秒，至少 30 份样本；记录上传后到可检索的时长及外部接口耗时。大 PDF 不适用该目标，另行测量。

**NFR-PERF-004 限流：**超过配置的 AI 并发容量时应返回可理解的容量限制，不得无限排队占用普通业务连接。并发初始容量不低于上述试点验收负载；单轮调度必须在 60 秒触发终止流程。

**NFR-PERF-005 完成率：**正常依赖、合法输入及不超过上述容量的请求中，普通读取与助手请求的系统执行完成率分别应达到 99%。用户主动取消、故意注入的依赖错误单独报告；无依据但正确结束回答属于完成，不得把系统异常或容量内的 429 从正常负载统计中剔除。此数值同属建议验收门槛。

### 9.2 安全与隐私

**NFR-SEC-001 授权覆盖：**全部私有数据接口、状态接口、引用接口及工具入口均纳入认证和权限测试，无已知跨用户读取或写入；管理员无默认读取他人计划的接口。

**NFR-SEC-002 凭据与传输：**非本机部署使用加密传输；凭据采用不可逆口令摘要，密钥仅服务端持有并可配置轮换。令牌不可出现在 URL、遥测、文件名或错误堆栈中。摘要算法及令牌验证参数由安全设计确定，禁止占位式明文实现。

**NFR-SEC-003 输入与输出：**数据库访问使用参数化机制，文件路径采用服务端标识，Markdown/HTML 渲染清除脚本、事件处理器和危险 URI。DOCX/PDF 解包与解析设置展开量、处理时间和资源限额，防止压缩炸弹或畸形文件耗尽资源；具体阈值列入 TBD-05。

**NFR-PRIV-001 最小记录：**日志、统计和审计默认不保存完整问答、课表、计划或资料正文，不记录密码、令牌或服务密钥。默认保留期按第 3 节；调试正文采样须独立开启、限定访问及到期清理。对外 AI 处理的资料范围在试点启用前确认。

### 9.3 可用性、恢复与数据完整性

**NFR-REL-001 降级：**模型、Embedding 或 MCP 故障时，直接业务课表读取、个人计划管理、用户及课程管理仍可使用；资料处理可失败但应保留任务状态。

**NFR-REL-002 运行恢复：**服务重启不得重复创建计划或发布半批文档。未完成任务在启动后 60 秒内被扫描；无法继续的请求明确标记失败；正常依赖恢复后，清理和删除按 5 分钟目标完成或产生告警。

**NFR-REL-003 备份：**试点启用前确定并冻结 RPO、RTO、备份周期、范围与责任人，覆盖关系数据、文档原件、配置和密钥引用；向量可从原件重建，恢复时间计入 RTO。至少执行一次包含删除标记与幂等结果的恢复演练。具体数值为 TBD-02，未确认及验证前不得进入试点。

### 9.4 易用性、兼容性与可观测性

**NFR-UX-001 反馈：**输入错误应明确字段及原因；状态不能仅用颜色表达；保存结果必须能打开对应计划。主要表单和操作支持键盘，流式内容不持续抢夺焦点。

**NFR-COMP-001 浏览器：**建议验收 Chrome、Edge 在试点冻结日的当前稳定版及前一主要版本。版本号记入测试报告，不在本文承诺未来所有版本。至少覆盖 1,366×768 桌面和 390×844 窄屏的核心学生流程；复杂后台表格可在窄屏横向滚动。

**NFR-OBS-001 追踪：**一个用户请求跨业务服务、MCP、外部调用和写入操作时能通过 request_id 关联。统计能区分 empty、failed、cancelled、timeout 和 succeeded；幂等重试不计作新的计划创建。

### 9.5 AI 质量

**NFR-AI-001 固定评测：**至少 50 条问题：有依据 20、未覆盖 10、课表 10、计划与重试 10；另设权限、注入、冲突资料和服务故障场景。固定评测中课表准确、无依据处理、写入正确与隔离要求全部通过；有依据答案及引用联合通过率≥90%。

正确率以人工预先标注的资料、事实和预期行为评定，不能仅由模型自评。样本通过不构成对所有开放输入的保证；模型、检索参数或关键提示调整后重新执行受影响评测。

## 10. 主要用例规格

### UC-01 查询本人明日课表

- 参与者：已启用学生。
- 前置：有效会话；学校时区已配置。
- 主流程：提交问题 → 系统确定明日完整日期 → 调用本人课表工具 → 按真实记录回答。
- 分支：日期歧义补问；无记录说明无安排；工具失败说明不可读取。
- 后置：无数据变更；回答与对应日期的普通课表页面一致。
- 关联：FR-SCH-001/002、FR-GUARD-001。

### UC-02 依据课程资料回答问题

- 参与者：已启用学生或管理员。
- 前置：登录；共享资料可为空。
- 主流程：提交规定类问题 → 检索有效资料 → 检查依据 → 回答并提供可展开引用。
- 分支：全库为空、依据不足、资料冲突、检索失败分别处理；无有效引用不伪装有据。
- 后置：无业务写入，必要过程与结果元数据可追踪。
- 关联：FR-QA-001—004、FR-DOC-006。

### UC-03 生成并保存学习计划

- 参与者：已启用学生。
- 前置：有效会话；当前指令明确要求保存，或用户选择特定草稿版本。
- 主流程：确认条件 → 按需查课表和资料 → 形成草稿快照 → 应用层授予许可 → 幂等写入 → 返回计划编号与详情。
- 分支：只规划则保持未保存；依据不足则补问；草稿过期重新生成；同键重试返回已有结果；写入未知先核实。
- 后置：成功时当前用户增加一份计划；同一轮和同一操作最多一份。
- 关联：FR-PLAN-001—005、FR-CHAT-006。

### UC-04 管理员批量发布资料

- 参与者：管理员。
- 前置：文件属于允许全员共享的范围，符合上传限制。
- 主流程：选择文件 → 提交批次 → 解析与向量化 → 全部成功 → 整批发布 → 学生可检索。
- 分支：格式或文本不合格整批不发布；依赖故障补偿清理；重启恢复任务。
- 后置：所有新资料同时可见，或整个批次不可见；其他批次不受影响。
- 关联：FR-DOC-001—004/007。

### UC-05 管理员维护课表

- 参与者：管理员。
- 前置：学生和课程存在且启用。
- 主流程：选择学生与课程 → 输入日期和时段 → 校验 → 无冲突保存 → 学生查询生效。
- 分支：精确重复拒绝；重叠可说明后确认；过期版本返回冲突；删除前确认摘要。
- 后置：页面与助手读取相同数据源，操作有审计。
- 关联：FR-SCH-003/004、FR-OPS-001。

## 11. 验收测试与发布门槛
