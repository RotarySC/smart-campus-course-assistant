**对「按并集实现」是否合理的判断**：**合理**，理由三条：

2. **可回收**：一旦后端确认，删掉一个分支即可，无迁移成本；
3. **已留痕**：不是在文档里悄悄扩大集合，而是显式写「登记未抹平 + 在确认前不得删除」，这正是可核对性要求的行为。
> 唯一建议：后端确认后应同步更新 `API-REFERENCE.md` §0（它现在把 `FORBIDDEN` 单列为「SRS §8 独有」），避免这份「机械生成物」长期与 openapi 不一致却无提示。
